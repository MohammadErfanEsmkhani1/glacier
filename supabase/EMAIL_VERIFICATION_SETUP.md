# Glacier email-link verification setup

Glacier registration now uses Supabase's built-in confirmation email link. The registration popup stays open in the browser that submitted the credentials. If the link is opened on a different device, that device securely publishes the confirmation token to a short-lived handoff; the original browser consumes it and receives the Supabase session.

## 1. Apply the database migration

Run `supabase/migrations/202611170001_glacier_email_handoff.sql` in the Supabase SQL Editor. It creates a private table used only for short-lived confirmation handoffs. Anonymous and authenticated clients have no direct table permissions; the Edge Function uses the service role.

## 2. Deploy the Edge Function

Deploy `supabase/functions/email-verification-handoff/index.ts` as `email-verification-handoff`.

The repository includes `supabase/config.toml` with JWT verification disabled for this function because a new registrant has no Supabase session yet. The function validates the browser origin, validates a random challenge secret, hashes that secret before storage, and only accepts an email token for a pre-created, unexpired challenge.

Use the Supabase CLI from the repository root:

```bash
supabase functions deploy email-verification-handoff
```

The function uses the platform-provided `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` environment variables. Never put the service-role key in Vercel, frontend code, or GitHub.

## 3. Require email confirmation

In Supabase Dashboard, open **Authentication → Providers → Email** and enable **Confirm email**.

## 4. Configure the Confirm signup email template

Open **Authentication → Email Templates → Confirm signup**. Replace the confirmation link with a link based on `{{ .RedirectTo }}` and `{{ .TokenHash }}`. The redirect URL generated by Glacier already contains the unique `handoff_id`.

Use this link in the HTML template:

```html
<a href="{{ .RedirectTo }}&token_hash={{ .TokenHash }}&type=email">Confirm my email</a>
```

You can use a friendly message such as:

```html
<div style="margin:0;padding:40px 16px;background:#100d12;color:#f4eff5;font-family:Arial,sans-serif;">
  <div style="max-width:480px;margin:0 auto;padding:36px 30px;border:1px solid #39313d;border-radius:20px;background:#1b1620;">
    <p style="margin:0 0 22px;color:#c5a8e8;font-size:11px;font-weight:700;letter-spacing:3px;">GLACIER</p>
    <h1 style="margin:0 0 14px;font-family:Georgia,serif;font-size:30px;font-weight:400;">One small step before you settle in.</h1>
    <p style="margin:0 0 24px;color:#c8c0cc;font-size:15px;line-height:1.7;">We're glad you're here. Confirm your email address and your Glacier account will be ready.</p>
    <a href="{{ .RedirectTo }}&token_hash={{ .TokenHash }}&type=email" style="display:inline-block;padding:14px 24px;border-radius:999px;background:#c5a8e8;color:#17111d;text-decoration:none;font-weight:700;">Confirm my email</a>
    <p style="margin:24px 0 0;color:#a99eae;font-size:13px;line-height:1.7;">If you didn't ask to create a Glacier account, you can safely ignore this email.</p>
  </div>
</div>
```

Important:
- Do not use the default `{{ .ConfirmationURL }}` in this template. It confirms the account in the browser that opens the link, which would bypass the original-browser handoff.
- The link must preserve the `handoff_id` query parameter from `{{ .RedirectTo }}`.
- Add `https://glacier-beta-coral.vercel.app/auth/confirm` to **Authentication → URL Configuration → Redirect URLs**. Also add the exact preview callback URL if testing a Vercel preview.
- Confirm that the Supabase project's Site URL is the production Glacier URL.

## 5. Test the full flow

1. Open Glacier in Browser A and register with an email address you control.
2. Leave the friendly verification popup open in Browser A.
3. Open the confirmation email on a different device or browser.
4. The email link should show a friendly confirmation page there.
5. Browser A should automatically complete verification and sign in.
6. Repeat with the email link opened in the same browser to verify the same-browser case.

The handoff expires after 30 minutes. The token is only published once, and the browser secret is stored only in that browser's local storage. Closing the popup using **Use a different email** clears the local handoff from that browser; the pending challenge expires automatically.

## 6. Bot protection and email delivery

Glacier keeps the existing optional Cloudflare Turnstile widget. To activate it, create a Turnstile widget, enable CAPTCHA under Supabase **Authentication → Bot and Abuse Protection**, add the Turnstile secret in Supabase, and set the public site key as `VITE_TURNSTILE_SITE_KEY` in Vercel. Never expose the Turnstile secret in frontend variables.

Supabase's built-in email provider is intended for testing and has a low sending allowance. Configure a suitable SMTP provider under **Authentication → SMTP Settings** before opening registration publicly. Review Supabase Auth rate limits as well.

## Important database detail

Supabase's standard `signUp()` operation creates a pending, unconfirmed row in `auth.users` before the email link is clicked. This flow cannot defer that Auth row until confirmation. Glacier does not create a public profile or grant access to authenticated app features until the user confirms their email and receives a session.
